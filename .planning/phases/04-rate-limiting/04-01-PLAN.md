2. Create `app/src/lib/server/rate-limit.ts`:
   - Import Ratelimit from @upstash/ratelimit
   - Import Redis from @upstash/redis
   - Import building from $app/environment
   - Use lazy initialization pattern (like supabase-admin.ts):
     - Declare `let ratelimit: Ratelimit | null = null`
     - Create `getRateLimiter()` function that:
       - Returns null if `building` is true
       - Lazily creates Ratelimit instance on first call
       - Caches instance for subsequent calls
   - Configure Ratelimit with:
     - Redis.fromEnv() for client (reads UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN)
     - Ratelimit.slidingWindow(100, '1 m') - 100 requests per minute
     - prefix: 'leadrfeeds_api' to namespace keys
     - analytics: true for visibility
   - Export `checkRateLimit(keyId: string)` function that:
     - Gets ratelimiter via getRateLimiter()
     - If null (building), return { allowed: true, headers: {} } to skip during build
     - Calls ratelimit.limit(keyId)
     - Returns { allowed: boolean, headers: Record<string, string>, retryAfter?: number }
     - Headers include: X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset
     - If not allowed, calculate retryAfter as Math.ceil((reset - Date.now()) / 1000)
  </action>

<task type="auto">
  <name>Task 2: Integrate rate limiting into hooks.server.ts using sequence()</name>
  <files>

  </files>
  <action>
1. Update `app/src/app.d.ts`:
   - Add `rateLimitHeaders?: Record<string, string>` to App.Locals interface

2. Refactor `app/src/hooks.server.ts`:
   - Import { sequence } from '@sveltejs/kit/hooks'
   - Import { checkRateLimit } from '$lib/server/rate-limit'
   - Split existing logic into `authHandler`:
     - Keep all existing auth logic
     - Return resolve(event) at the end
   - Create new `rateLimitHandler`:
     - Skip if not /api/v1/* route (return resolve)
     - Skip if no apiUser in locals (auth failed, already returning 401)
     - Call checkRateLimit(event.locals.apiUser.keyId)
     - If not allowed:
       - Use rateLimited() helper from api-response.ts
       - Add rate limit headers to the 429 response
       - Return the response
     - If allowed:
       - Store headers in event.locals.rateLimitHeaders
       - Call resolve(event)
       - Add rate limit headers to the response
       - Return the response
   - Export handle = sequence(authHandler, rateLimitHandler)

Key implementation details:
- Auth handler runs first (validates key, sets apiUser)
- Rate limit handler runs second (only if auth passed)
- Rate limit headers added to ALL responses (success and 429)
- Use Object.entries(headers).forEach to add headers
  </action>
