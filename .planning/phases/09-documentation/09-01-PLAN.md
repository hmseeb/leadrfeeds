    1. Create openapi-spec.ts with complete OpenAPI 3.1.0 specification:

       Info:
       - title: "LeadrFeeds API"
       - version: "1.0.0"
       - description: "Read-only API for accessing your feed data programmatically."

       Servers:
       - url: "https://leadrfeeds.com/api/v1" (production)

       Security:
       - bearerAuth scheme (http bearer)
       - description: "API key from Settings > API Keys"

       Components/Schemas:
       - Error: { error: { code, message, status } }
       - Entry: { id, title, url, description, content, author, published_at, feed, is_read, is_starred }
       - Feed: { id, title, url, site_url, description, category, image, unread_count, subscribed_at }
       - Collection: { id, name, icon_name, display_order, feed_count, unread_count, feeds[] }
       - Stats: { total_unread, total_starred, feeds[] }
       - PaginationMeta: { next_cursor, has_more, limit }

       Paths (document all 4 endpoints with full details):

       /entries:
       - GET: List feed entries
       - Parameters: cursor, limit, feed_id, collection_id, category, start_date, end_date, is_read, is_starred, search
       - Response 200: { data: Entry[], meta: PaginationMeta }
       - Response 400, 401, 429, 500 with Error schema

       /feeds:
       - GET: List subscribed feeds
       - No parameters (returns all)
       - Response 200: { data: Feed[] }

       /collections:
       - GET: List collections with feeds
       - No parameters
       - Response 200: { data: Collection[] }

       /stats:
       - GET: Get aggregate statistics
       - No parameters
       - Response 200: { data: Stats }

       Export as `openApiSpec` const with `as const` for type safety.

    2. Create +server.ts endpoint:
       - Import openApiSpec from $lib/data/openapi-spec
       - GET handler returns JSON.stringify(openApiSpec, null, 2)
       - Headers: Content-Type: application/json
       - No Content-Disposition (allow viewing in browser, not forced download)
