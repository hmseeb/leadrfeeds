  <action>
Refactor supabase.ts to use lazy initialization pattern:

1. Remove the top-level throw statements (lines 12-18)
2. Remove the top-level `supabaseAdmin` constant
3. Add a module-level variable to cache the client: `let _supabaseAdmin: SupabaseClient<Database> | null = null`
4. Export a function `getSupabaseAdmin()` that:
   - Returns cached client if already initialized
   - Reads env vars when called (not at module load)
   - Throws descriptive error if SUPABASE_SERVICE_ROLE_KEY missing
   - Throws descriptive error if PUBLIC_SUPABASE_URL missing
   - Creates client, caches it, and returns it
5. Keep the import statements and type imports unchanged
6. Update the JSDoc to reflect it's now a getter function

The key change: Error checking moves from module scope to function scope. The module can be safely imported without env vars present.

Example structure:
```typescript
let _supabaseAdmin: SupabaseClient<Database> | null = null;

export function getSupabaseAdmin(): SupabaseClient<Database> {
  if (_supabaseAdmin) return _supabaseAdmin;

  const serviceKey = privateEnv.SUPABASE_SERVICE_ROLE_KEY;
  const supabaseUrl = publicEnv.PUBLIC_SUPABASE_URL;

  if (!serviceKey) {
    throw new Error('SUPABASE_SERVICE_ROLE_KEY is not set');
  }
  if (!supabaseUrl) {
    throw new Error('PUBLIC_SUPABASE_URL is not set');
  }

  _supabaseAdmin = createClient<Database>(supabaseUrl, serviceKey, { ... });
  return _supabaseAdmin;
}
```
